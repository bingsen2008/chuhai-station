# 出海实验站

短剧出海商业化试点的本地草稿台。五层实验塔对应一条固定顺序：成片准入、海外投放策略、数据对账、商业分析、选题反馈。

这一版只在浏览器里编辑草稿。它能展示已经创建的角色名册，并复制一段手动交接文本，供你自己粘贴到对应 Bot 的对话。它不会派发 Bot，不会查询在岗状态，也不会批准或执行花费。

## 运行

```bash
npm install
npm run dev
```

开发服务器监听 `4317`。本机打开 [http://127.0.0.1:4317](http://127.0.0.1:4317)。

```bash
npm test
npm run lint
npm run build
```

不需要密钥、账号或外部接口。

## 名册和状态

页面只收录这次说明里的六个角色：出海准入、海外投放策略、投放监控、选题反馈、靓仔、算盘。

三种状态分开写：

- 角色：已建立。这来自名册，不是运行时查询。
- 认证集成：未连接。
- 运行中任务：无。没有可读的运行时，因此不会显示在岗、空闲或已完成。

`src/lib/adapter.ts` 是明确的未连接边界。它不提供派发、鉴权、任务查询、花费或网络监控。

## 草稿存在哪里

试点配置、计划任务、策略、规则、证据、提议和反馈都写在这台浏览器的 `localStorage`。键名是 `haichu-experiment-station.draft.v1`。

导出的 JSON 会先做结构校验。导入会拒绝超限文件、未知字段、口令样式的字段、邮箱、电话号码，以及 `grokbot://` 链接。空着的基线和阈值保持为未填写，不会被当成 0。定时监控在校验里只能是关闭。

活动记录只追加本地编辑、复制交接文本、导入和导出。

## 仓库

源仓库仍是 Origin 私有库 `bro-lu/chuhai-station`。GitHub 只作为 GitHub Pages 的发布副本，不是 Vercel 的镜像。

`.github/workflows/pages.yml` 在推送到 GitHub 的 `main` 时执行 `npm run build`。Next.js 使用 `output: "export"`，产物在 `out/`。项目站点的资源前缀是 `/仓库名`；如果仓库名以 `.github.io` 结尾，前缀为空。

## 现在不能做的事

- 没有 Bot 运行时，交接是手动复制，不是派发。
- 没有广告或收入接口，没有花费许可，不能发布、暂停或改预算。
- 没有后台监控。规则草稿只供以后人工对照历史回放，默认视图里没有模拟告警。
- 不收集密码、令牌、邮箱或其他个人数据。
- 本地 `npm run dev` 只在这台机器上提供预览。公开 Pages 地址要等 GitHub 仓库创建并跑完 Actions 之后才存在。
