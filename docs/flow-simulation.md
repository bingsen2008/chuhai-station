# 业务流程模拟设计与验收

## 调查结论与改动范围

原站点以 `station-app.tsx` 的五层等距楼宇为入口。`catalog.ts` 定义楼层与席位，`roster.ts` 收录六个既有 Bot，`draft-context.tsx` / `storage.ts` 管理业务草稿，`onboarding.tsx` 曾另存各楼层数字进度。

旧引导没有保存当前楼层、任务交付物或日志。刷新后，草稿标题和楼层通过数恢复，当前选择却回到默认层；业务位置与交付物提示因此容易互相矛盾。原 docs 只有截图，README 描述的也是分层手工演示。

新版将事件模拟独立建模，业务流程是默认视图；原 `Tower` 几何和席位保持，作为辅助视图。完整原草稿功能迁入 `draft-workspace.tsx`，通过页面末尾折叠入口按需挂载；草稿与模拟案件不互相覆盖。旧分层引导被替换。

## 流程与角色

主线为：出海准入 → 海外投放策略 → **用户审批** → 模拟投放 / 监控 → 算盘对账 → 选题反馈 → 下一轮策略 → 海外投放策略。

审批是实际的本地状态门槛：播放和单步都不能越过。只有点击批准才能继续；可以退回策略，修订后再次提交审批。所谓“一键跑通”是启动并跟随完整演示，遇到人工决策仍需用户点击。每次批准后继续播放，直到下一审批或本轮完成。

- 出海准入、海外投放策略、投放监控、算盘、选题反馈沿用既有名册命名。
- 靓仔是总控协调，异常时整理证据与选项，提交用户审批，不能代批。
- 业务专家是演示咨询角色，不新增真实 Bot、凭证或集成；规则咨询是策略的往返旁路。
- 知识卡片 K-001 是选题反馈的闭环交付物，无后台、无真实定时任务。

每张主线及旁路卡片包含输入、负责人、交付物、状态和下一步。状态同时使用中文、图标与颜色：○ 等待、◉ 进行中、✓ 通过、↶ 返工、! 异常升级。已通过节点的历史退回/异常保留在日志中。

## 场景差异

| 场景 | 可观察到的路径与结果 |
| --- | --- |
| 正常闭环 | 准入通过 → 咨询专家 → 用户审批 → 四批模拟样本 → 对账 → 知识卡片 → 下一轮提纲回流策略 |
| 准入退回 | 准入标为返工 → 靓仔协调补字幕授权材料 → 材料 v2 → 重新提交准入 → 继续主线 |
| 投放异常 | 第二批模拟花费 USD 160，超过示例阈值 USD 120 / 批 → 监控异常升级 → 靓仔协调 → 用户审批；可继续余下两批，也可结束观察，只用已有两批对账 |

所有场景首次投放前都需要人工演示审批。切换场景完整复位并暂停；重置保留所选场景与固定 seed，将速度重置为 1x。

## 引擎与数字

`src/lib/simulation/engine.ts` 是无 I/O 的纯函数模块，不使用 `Date.now`、`Math.random` 或网络。

- 默认固定 seed：20261107。32 位 LCG 只在样本事件推进，样本可复现。
- 每次 tick / step 恰好消费一个离散事件；暂停的 tick 是无操作。
- 定时器只是 UI 的事件触发器，不按真实经过时间补跑，不在页面关闭后推进。
- `EngineState` 同时包含节点、当前节点、有向交接、交付物、累计指标、日志、审批门槛、剩余事件、操作历史、速度和播放状态。
- 每个事件携带指标增量；显示数字等于所有已发生事件的增量和，非随机重绘。
- 金额以整数美分累计，显示为 USD。示例预算 USD 500 是上限提议，不是余额或真实花费许可。
- 曝光、点击单位为次；收入是同实验窗口的模拟归因毛收入，非已结算净现金。
- ROI =（模拟归因毛收入 − 模拟花费）/ 模拟花费。零花费时未定义。未计平台分成、税费与退款，不构成效果承诺。

0.5 / 1 / 2 / 4x 仅改变事件播放间隔，基础间隔 1600ms；不改变事件值。光点只对应 `state.transition`，每个 Tick 的交接只移动一次，非循环动画；暂停保留同一个光点并冻结动画，无交接事件时移除光点。单步显示静态交接。减少动态效果偏好下隐藏光点，只显示状态与路径高亮。

## 存储一致性

新键 `chuhai-station.flow-simulation.v2`，`schemaVersion: 2`。

保存整份引擎快照，以及引导偏好和视图。恢复流程：

1. 校验版本、场景、seed、速度、操作历史等结构；限制文件大小与历史数量，避免无界恢复。
2. 从固定 seed 重放每条单步/审批操作。
3. 将重建结果与存储中的完整引擎快照比较，包括指标、节点、当前节点、交付物、日志与剩余事件。
4. 完全一致才恢复；播放状态强制设为暂停。
5. 不兼容、损坏或矛盾时整份复位，显示原因，不进行部分拼接。

旧 `chuhai-station.experience.v1` 只迁移合法布尔引导偏好。旧数字楼层进度缺少完整信息，因此明确忽略并复位。旧键和草稿键 `haichu-experiment-station.draft.v1` 不被删除。存储读取/写入异常会提示，本页仍可继续使用。

## 交互与无障碍

默认视图为原创暗色 2D 无限画布式树状拓扑，无画布依赖库。顶层橙色「卢哥」负责人工决策，第二层青色「靓仔」负责总控，多张紫/绿/蓝业务 Agent 卡片并列；业务专家和材料返工属于侧路。深色半透明卡片以细边和轻微光晕区分角色。

组织指令线为橙色，汇报/升级线为青色虚线，业务交接线为紫色，咨询侧路为蓝色虚线；全部使用贝塞尔曲线和方向箭头，并标注任务输入、输出与交接内容。实际事件路径按交接类型分色。独立的主业务链显示 01–07 顺序、当前/下一步与交付物，避免把组织关系当成业务顺序；策略到监控的横线明确标注「审批后」。

桌面可拖动空白或节点背景平移；画布聚焦时方向键平移、+/- 缩放、Home 适应、0 复位。滚轮只在画布聚焦时以光标为中心缩放。工具栏提供适应、复位、缩放及纵向业务流切换。适应会将全部节点置于视口，复位恢复 100% 比例和初始偏移。相机不保存；不改变引擎状态。

800px 及以下自动显示纵向业务流与折叠节点，不需要横向拖动画布。当前节点默认展开；其他节点可展开查看输入、指标、交付物和下一步；仍可使用复位。桌面也可主动切换纵向业务流。楼宇继续作为次级视图，切换视图不推进 Tick。

指标分布在业务卡片内：监控显示累计花费、曝光和点击；对账显示归因毛收入和 ROI；其他卡片显示预算、处理/交付事件数。增量为当前 Tick 的变化，ROI 增量按百分点展示。点击指标行打开深色弹窗，包含事件柱状图、可读表格、计量口径和无样本提示。柱高保留正负数标识。弹窗限制 Tab 焦点、Esc/关闭按钮/遮罩可关闭，关闭后恢复触发按钮焦点。

顶部固定标识“模拟数据 · 未连接真实业务”。首屏案件卡、当前节点、下一步、下一交付物与待审批数可见，状态条滚动保留。卢哥的橙红「待办 N 件」胶囊打开本地审批弹窗；无待办时不预授权，有待办时明确通过或退回返工（异常可结束观察并对账）。关闭弹窗不做决定，播放与单步均无法跨过未审批门槛。原审批面板仍提供直接决策入口。首次引导可跳过、重开并保存。

事件日志使用 `role="log"`、`aria-live="polite"` 和 additions 通告；列表按事件顺序追加，可键盘聚焦滚动。键盘焦点有明显轮廓；减少动态效果时不播放位移动画。

## 边界

所有案件、规则、样本、阈值和交付物都是固定演示。没有真实广告平台、消息、058 算力或其他外部 API 调用，没有登录或凭证输入，不派发 Bot。本轮完成后停在下一轮提纲回流，不自动开启第二轮；可以重置重放。

本地存档依赖当前浏览器，不跨设备同步。原草稿编辑工作台与模拟案件独立，不从用户草稿自动生成真实业务结论。
